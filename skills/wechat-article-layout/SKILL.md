# 公众号排版（Markdown → 公众号）

用户给一篇 Markdown 文章，产出一个 `<slug>-公众号排版.html`。用 Chrome 打开后：
- 顶部可以切换 **10 套风格**（结构不同，不只是换色）和 **15 套配色**，两者自由组合，一共 150 种：
  - 风格：`std` 标准（PART 大标题、荧光笔、圆角卡片）、`mag` 杂志（宋体标题居中、细线、留白多）、`min` 极简（黑白、无底色、左对齐）、`geek` 极客（等宽字标签、虚线框）、`bold` 醒目（大色块标题、粗圆角）、`neo` 质感（巨型数字和大引号做底纹、细线描边、柔和阴影、浅色扁平金句卡，设计感最强）、`note` 手账（便签贴纸编号、荧光笔、虚线和纸胶带）、`zen` 雅致（印章编号壹贰叁、宋体标题居中、双线金句）、`bento` 卡片（大圆角色块、胶囊编号、轻盈扁平）、`dark` 暗夜（整篇深色底、亮色强调，科技感）。
  - 配色：品牌橙、科技蓝、薄荷绿、墨黑、藏青金、葡萄紫、胭脂红、琥珀、莫兰迪、松柏金、孔雀青、雾霾蓝、橄榄绿、可可棕、豆沙粉。标题卡、大字海报、质感横幅都跟着配色换。
  - terminal 在所有风格里长得一样；提示词卡在手账、雅致、卡片、暗夜里有各自的样子。
- 填一次头像 GIF 地址（会记住）。
- 点「复制全文到公众号」，到公众号编辑器正文里粘贴。
- 也可以只复制横幅，或只复制正文。
- 「复制 Markdown」复制的是纯正文（去掉了图片、视频、动画卡和 [截图]/[可补] 这类占位），用来贴到朱雀做 AI 检测。

## 步骤

**省时规则（一定要守）**：
- 脚本已经写好、测过。**不要读 `layout.py` / `banner.py` 源码，不要读 examples 里的示例**，照下面的命令跑就行。只有脚本报错时才去看报错那一段代码。
- **不要自己另写清理脚本**。飞书导出的转义反斜杠、`[xxx.mp4]` 视频标记、飞书临时图片链接，`layout.py` 都会自动处理和提示。
- **默认不截图**。`layout.py` 跑完会打印一份文字自查报告，看报告就够了。用户说「截图看看」时才截，最多一张整页图。动画卡要在页面打开 6–8 秒时截，0 秒时还没出现，是空白的。

1. **先问横幅风格（必须问，用 AskUserQuestion）**，四个选项：
   - **大字海报**：左边两行大标题，右边一组大元素，1246×460，只播一次。按手机可读设计，字最大。正文切到质感风格时，横幅会自动换成质感版（白卡、细线、柔和阴影）。
   - **默认风格**：头像 + 像素口号 + 场景动画，1246×220，循环播放。
   - **标题卡风格**：左边放文章标题，右栏 12 种版式，1246×420，只播一次。
   - **不要横幅**。
   用户点名要「质感横幅」时用 `"style":"neo"`，任何正文风格下都是质感版。用户不在场、没法问时，用默认风格，并在交付时说明。
2. **准备脚本**：
   - skill 目录里有 `scripts/layout.py` 和 `scripts/banner.py`（zip 安装版）时，把这两个文件复制到工作目录，一条 `cp` 命令搞定。
   - 没有 `scripts/` 时（只有这份 SKILL.md），把文末的 `layout.py` 写到工作目录，再加载 `wechat-opening-banner` skill，把它的 `banner.py` 原样写到同一目录。
3. **写横幅 spec**，存成 `banner.json`。规则见 `wechat-opening-banner` skill（已经熟悉的话不用再加载）：
   - 默认风格：选一个场景模板。
   - 标题卡风格：`"style":"card"`，从 12 种右栏里挑一个，不写 `theme`。
   - 大字海报：`"style":"poster"`，内容写在 `"poster"` 里：`eyebrow`、`title1`、`title2`（每行 ≤8 个汉字）、`right`（`flow` / `tags` / `steps` / `stat` 四选一）。`ask`、`result`、`tags`（3 个关键词）、`big`（1–2 个字符的底纹字）都写上，质感版要用。不写 `theme`。完整示例是 `examples/banner-poster.json`。
4. **整理 Markdown**，复制原文为 `article.md`，然后只做**局部修改**（用 Edit 改几处，不要整篇重新输出）：
   - 用户的原文只做必要的标记，不改写内容。
   - 原文里句中的 `**加粗**` 一律保留，它会排成荧光笔。不要把它拆出来改成金句卡或引用卡，否则「……让我停住了：」后面会突然断开，接一张大卡。金句卡只用在原文本来就单独成段的那句话上。
   - 按下面的语法把引用、提示词、长图、步骤等标出来。
   - 二级标题前的「一、二、」不用删，脚本会自动去掉。图片、视频下面的短说明不用标，脚本会自动排成图注。
   - 二级标题可以补英文副标题（`## 标题 | ENGLISH`），没有把握就不加。
   - 适合做成动画的表格、步骤、长指令，按「动画 SVG 卡」一节的规则转成 `svg-xxx` 代码块。一篇最多 3 张。
5. **运行**：
   `python3 layout.py article.md --banner banner.json --out out`（用户指定了风格或配色时加 `--style` `--theme`）
   不要横幅时去掉 `--banner`。命令会打印「统计」和「发布前要处理」。如果报告里有**标记没配对**，回到第 4 步修好再跑一次；图片链接、视频占位这类问题不用修，交付时转告用户。
6. **交付 HTML**，把自查报告里「发布前要处理」的条目原样转告用户，再提醒：
   - 在 WorkBuddy 的产物里点开就能预览和复制；别的聊天窗口预览写不了剪贴板时，用 Chrome 直接打开文件。
   - 粘贴后发预览到手机确认。

## Markdown 写法 → 公众号组件

| 写法 | 效果 |
|---|---|
| `---` 开头的 front matter：`title` `slug` `h2` `theme` `outro` | 文章设置（见下） |
| `# 标题` | 只当文章标题用，不进正文（公众号标题栏另填） |
| `## 标题` 或 `## 标题 \| ENGLISH SUB` | **PART 01 大标题**：大号编号 + 竖线 + 标题 + 英文小字。原文标题自带的「一、」「1.」会自动去掉，不用手动删。front matter 写 `h2: pill` 时改成原来的橙色胶囊「一、标题」（只在标准风格下生效） |
| `### 第一步 打开设置` / `### Step 1 xxx` | **步骤标签**：深色胶囊「第一步」+ 粗体标题 |
| `### 普通小标题` | 左侧主题色短竖条 + 粗体 |
| `**重点**` | **荧光笔加粗**：黑色粗体，下半截淡黄色底 |
| `==重点==` | 主题色色块白字（原来的橙底白字强调）。适合很短的数字、口令，一篇两三处 |
| `++下划线++` 或 `<u>…</u>` | 主题色下划线，每种风格画法不同（实线、虚线、细线）。适合提醒和引导，比如「不用配置」「评论区留言」 |
| `` `code` `` | 行内代码，主题色浅底 |
| `> 引用` | **引用卡**：浅主题色底、左侧粗色条、淡色大引号 |
| `> [!QUOTE] 一句话` | **金句卡**：居中大字，上下两条短色线 |
| `> [!TIP]` `> [!NOTE]` `> [!WARN]` `> [!TLDR]` | 提示卡：小技巧、说明、注意（橙黄）、省流版 |
| ` ```bash ` / ` ```text ` 等普通代码块 | **terminal**：黑底、红黄绿三个点、单行不换行，可以横向滑动（保持原样式） |
| ` ```prompt 文件名.txt ` | **长提示词卡 A**：黑色 PROMPT 标签 + 「文件名 · 上下滑动查看」，限高 320px，可上下滑动；13px 等宽字、冷灰蓝色，和正文区分开，`【…】` 用主题色加粗 |
| ` ```promptbox 标题 ` | **长提示词卡 B**：虚线框 + 图标 +「滑动查看完整提示词」，限高可滑 |
| `![说明](url "long")` 或 ` ```longimage 标题 ` 里写一行 url | **长图卡**：虚线框「滑动查看长图」，限高 420px，可上下滑动 |
| `![图注](url)` | 圆角图片 + 灰色居中图注（alt 写 image 时不显示图注） |
| 图片或视频下面紧跟的一行短句（46 字以内、结尾没有标点） | **自动当图注**：灰色小字居中。统计里的「图注 N」就是这种。不想要就在 front matter 写 `caption: off` |
| `^ 一行说明` | 手动图注，放在任何位置都行 |
| `- 列表` / `1. 列表` | 主题色圆点 / 编号小方块。编号沿用原文写的数字，条目之间有空行也算同一个列表，缩进两格是子条目 |
| 表格 | 浅色表头、细边框 |
| `---` | 三个小圆点分隔 |
| 单独一行 `[xxx.mp4]`（飞书导出的视频） | 虚线占位框「此处放视频：xxx.mp4」，提醒在公众号里手动插视频 |
| `[文字](链接)` | 公众号文章链接保留可点；外链变成主题色文字 + 角标，文末自动生成「参考链接」 |

## 动画 SVG 卡（```svg-xxx 代码块）

表格、步骤、时间线、长指令这类内容，写成 `svg-xxx` 代码块就会排成会动的 SVG 卡，配色跟着当前皮肤走。卡片外框和标题会跟着风格变（比如质感是白卡加细线和柔和阴影，极简是黑色标题栏），里面的内容各风格通用。规则：
- 只用 SMIL，不用 id 和 class。
- 标题胶囊从第一帧就能看到。
- 10 秒一轮循环播放。读者往下滑到卡片时，它还在动。

| 写法 | 画面 | 适合 |
|---|---|---|
| ` ```svg-table 标题 ` + 标准 Markdown 表格 | 表头先出，每行从左滑入，标 ★ 的行加主题色边框 | 对比表、功能清单 |
| ` ```svg-bars 标题 `，每行 `名称 \| 数值 \| 显示文字` | 横向柱子依次长出，数值弹出；★ 那行（默认最大值）用主题色 | 有真实数字的对比 |
| ` ```svg-steps 标题 `，每行 `步骤 \| 补充说明` | 步骤卡依次滑入，右侧对勾画出 | 抄作业、操作步骤（3–5 步） |
| ` ```svg-timeline 标题 `，每行 `时间 \| 事件` | 横线画过去，节点依次点亮（最多 6 个） | 一天 / 一周 / 版本节点 |
| ` ```svg-breakdown 标题 `，每行 `标签 \| 内容` | 标签胶囊弹出，荧光笔逐行扫过；★ 那行是实心色块、白字 | 长指令、长提示词拆要素 |
| ` ```svg-compare 标题 `，第一行 `左标题 \| 右标题`，之后每行 `以前 \| 现在` | 左边灰色 ×，右边主题色 ✓，逐行出现 | 以前 vs 现在、A vs B |
| ` ```svg-concept 标题 `：第一行一句大白话；`旧东西 \| 节点 \| 节点`；`新东西 \| 节点 \| 节点 \| 节点`；可选一行 `! 关键差别…` | 灰色虚线是旧的，主题色实线一段段画出来、节点依次点亮，最后虚线框圈出关键差别 | 一眼看懂一个新概念 |
| ` ```svg-phone 标题 `：第一行写「按 XX 演示」；之后每行 `功能名 \| 谁说的或时间 \| 气泡里的话`（谁说的写「我」时气泡在右边） | 左边一台手机一幕幕轮播，右边功能列表的高亮跟着走，3–5 幕 | 随时间变化的流程，截图只能截一帧的那种 |

- `svg-phone` 是示意，不是真实截图：第一行一定要写清「按 XX 演示」，真实截图另外放。
- 任何一种卡（`svg-phone` 除外），在最后加一行 `> 一句话`，会变成卡片底部的金句，并画一条下划线。
- 在某一行任意位置加 `★`，表示这一行是重点。
- 文字太长会自动换行，但标签和步骤标题最好控制在 12 字以内。

**什么时候由 skill 自动转换**（第 3 步整理 Markdown 时）：
- 有一个 3 行以上、你想让读者一眼看懂的表格 → 转 `svg-table`；全是数字对比 → 转 `svg-bars`。
- 「第一步 / 第二步 / 第三步」连续出现，而且每步都很短 → 转 `svg-steps`。原来的步骤小标题不再保留。
- 很长的提示词，用户想讲清它的结构 → 在提示词卡前面加一张 `svg-breakdown`。提示词卡本身保留。
- 一篇最多 3 张动画卡。截图能证明的内容不要转（截图比 SVG 可信）。拿不准就不转，交付时列出「这几处可以做成动画卡」，问用户要不要。

Front matter：
- `h2`：`part`（默认）或 `pill`。
- `style`：默认风格，`std` `mag` `min` `geek` `bold` `neo` `note` `zen` `bento` `dark`，默认 `std`。
- `theme`：默认配色，可选 `orange` `blue` `teal` `ink` `navy` `violet` `rose` `amber` `morandi` `forest` `petrol` `mist` `matcha` `cocoa` `dusty`，默认 `orange`。
- `style` 和 `theme` 也可以用命令行 `--style mag --theme navy` 指定，不用改文章。指定了就按指定的打开；没指定时用上次在页面里选过的。
- `caption`：`off` 时关掉自动图注。
- `outro`：`false` 时不加文末作者卡。作者卡用同一个头像 GIF，文案可以用 `author`、`slogan`、`outro_cta` 改。

## 设计规则

- 正文 16px，行高 1.9，颜色 `#3F3F46`，两端对齐。提示词 13px，颜色 `#52607A`。整页只有一个主题色。加粗用荧光笔，颜色跟主题色分开：琥珀皮肤用淡蓝，其他皮肤用淡黄。
- 新增配色时，在 `THEMES` 里加一行，五个色值是 main、soft、tint、line、mark。标题卡横幅会自动跟着用。配色的定法：主色压暗、降饱和（白字放在主色上对比度至少 5）；soft、tint、line 从主色同色相推出来，只带一点点颜色，不要用通用的冷灰蓝。
- **公众号会删掉没有文字的空元素**：只有宽高和底色、里面没字的 `<span>`（比如终端的红黄绿三个点、标题下的短线、分隔线、纸胶带）粘贴后会消失。脚本最后会把这类空元素统一画成同尺寸的小 SVG（`fix_empty`），新写组件时照常写空 span 就行，不要另想办法。渐变短线也会被转成一排逐渐变淡的细条，因为 SVG 渐变同样会被删。
- **大引号一律用 `quote_svg()` 画**，不要用 Georgia 字体打一个「“」：大多数安卓手机没有 Georgia，引号会掉下来压在文字上。
- 质感风格的金句卡不要用深色底，用户要的是苹果那种浅色扁平：浅底、无阴影无描边、超大引号当底纹（和大标题的巨型编号同一个手法）。
- 质感风格（`neo`）不要用实色错位投影和粗黑描边，用户明确说过那样显得廉价；阴影一律用柔和的扩散阴影，SVG 里不能用滤镜，就叠三层低透明度的色块。
- 新增风格时，在 `STYLES` 里加一行，再到各组件函数里按 `T["st"]` 加分支；没加分支的组件自动用标准风格的样子。手账、雅致、卡片、暗夜四套的组件写在 `x_*` 函数里（`NEW_ST`）。
- 暗夜（`dark`）整篇是深色底：没写分支的组件由 `dark_fix()` 统一把文字换成浅色，动画卡里的白卡片保持原样。微信开了深色模式时可能会被二次调色，发之前一定要用手机预览看一眼。手账的便签和纸胶带用了轻微旋转，也要预览确认。
- 用户没指定风格时用标准，不要替用户挑。用户说「换个风格看看」时不用重跑，告诉他在页面顶部点就行。
- 杂志风格的宋体标题在苹果手机上是宋体，部分安卓手机没有宋体，会显示成黑体。
- 不改写用户原文。只做排版标记，最多帮着补二级标题的英文副标题。
- 全部样式写成内联 style，不用 `<style>`、class、script。复制页本身的脚本不会进剪贴板。
- 渐变荧光笔、flex 布局、滑动卡在公众号里通常都能保留。粘贴后一定要发手机预览确认。

## 脚本

`scripts/layout.py`（排版）和 `scripts/banner.py`（横幅）都在 skill 目录里，直接复制到工作目录运行，不需要读源码。
